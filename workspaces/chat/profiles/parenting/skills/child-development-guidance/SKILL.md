# 儿童发展信息

## 目标

提供有弹性的发展阶段信息，帮助照护者关注变化趋势、环境和功能影响，而不是用单一时间点给孩子贴标签。

## 必要输入

- 孩子年龄和用户关心的领域；
- 具体观察、持续时间、变化趋势和出现情境；
- 家庭语言、健康、环境或既往情况等会影响理解的背景。

## 硬门禁

- 不根据简短描述诊断发育障碍、心理问题或疾病。
- 不把发展里程碑当作所有儿童必须在同一天达到的硬期限。
- 出现能力倒退、安全风险或持续影响日常功能的担忧时，不用居家建议替代专业评估。

## 执行流程

1. 明确用户关注的是语言、动作、认知、社交情绪还是生活能力。
2. 说明一般发展范围及个体差异，避免只给一个绝对年龄点。
3. 将用户观察放入频率、情境、趋势和功能影响中理解。
4. 给出少量可在日常环境中观察或支持的方式。
5. 说明哪些变化值得记录并向儿科或相关专业人士咨询。

## 输出契约

输出“一般信息、结合当前描述的观察重点、可尝试支持、需要专业咨询的条件”。措辞保持审慎，不制造确定诊断。

## References 与 Templates

本 Skill 不依赖额外文件。习惯方案使用 `routine-building`，具体冲突沟通使用 `parent-child-communication`。

## 边界

发展信息不能替代儿科、听力、语言或心理等专业评估。用户提供的地区、健康和教育背景不足时，明确结论限制。

## 示例

家长询问两岁语言表现时，应说明表达与理解都需要结合语言环境和变化趋势观察，并给互动建议；不要仅凭词汇数量下诊断。

## 常见错误

- 把平均年龄写成硬性截止线；
- 只列里程碑，不问具体情境；
- 对单次行为过度解释；
- 用“别担心”替代对持续担忧的评估建议。
