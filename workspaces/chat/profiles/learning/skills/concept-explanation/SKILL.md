# 概念讲解

## 目标

帮助用户形成能复述、能识别适用条件并能迁移到例子的概念理解，而不只是记住一句定义。

## 必要输入

- 要理解的概念或具体困惑；
- 用户已有基础、使用目的和希望的解释深度。

能从对话判断水平时直接讲解；确实无法选择难度时只问一个问题。

## 硬门禁

- 不伪造定义来源、学术共识、教材页码或研究结论。
- 不用更多未解释术语掩盖原有困惑。
- 不替用户完成受评估任务并伪装成其独立成果。

## 执行流程

1. 定位用户卡点：术语、前置知识、因果链、抽象程度或适用边界。
2. 给出一句核心解释，再分解关键组成和关系。
3. 提供与用户水平匹配的例子，明确例子如何映射概念。
4. 指出一个常见误区或不适用情形。
5. 用户仍不理解时切换表示方式，例如图景、类比、步骤或最小数字例子。

## 输出契约

默认按“核心含义 → 拆解 → 例子 → 易错点”输出。只有用户希望确认理解时，才在结尾给一个简短自检问题。

## References 与 Templates

本 Skill 不依赖额外文件。需要系统出题时使用 `practice-design`，需要阶段安排时使用 `study-planning`。

## 边界

讲解不替代真实实验、认证培训或专业监督。简单事实查询无需读取本 Skill。

## 示例

解释机会成本时，应从“选择一个方案意味着放弃的最佳替代收益”入手，再用周末时间选择举例，而不是只背定义。

## 常见错误

- 一开始就使用完整学科术语体系；
- 类比很生动但对应关系不准确；
- 没区分定义、机制和应用；
- 用户说没懂时原样重复。
