# 社媒内容创作

## 目标

把用户的真实素材转化为符合发布渠道、受众和内容目标的标题与正文，同时保持可信和自然。

## 必要输入

- 发布渠道、目标受众和内容目的；
- 必须使用的事实、素材或产品信息；
- 期望长度、语气、形式以及禁用表达。

缺少渠道但渠道会显著改变成稿时，只询问渠道。遇到价格、品牌、材质、尺码等缺失但不能虚构的事实时：如果缺少该信息导致无法形成有意义的内容，只问一个最关键问题；如果用户已经明确要求马上输出、输出整个文案或给出完整版本，则立即用 `[待填写：品牌]`、`[待填写：真实价格]`、`[待填写：材质]` 等具名占位符完成可用草稿，不重复列出一组问题。进入这种交付模式后，不得再次要求用户先提供信息，也不得只给格式示例或交付承诺。

## 硬门禁

- 不虚构亲身体验、用户评价、销量、功效、资质或数据。
- 不用健康焦虑、羞耻、歧视或无法兑现的承诺换取点击。
- 涉及儿童内容时避免公开可识别的隐私信息。

## 执行流程

1. 提炼唯一内容重点和用户希望读者采取的动作。
2. 选择适合渠道的叙事角度、信息密度和开头方式，不机械堆砌热词。
3. 用用户素材建立正文结构，明确事实与主观感受。
4. 生成与正文一致的标题；需要多个版本时改变角度而非只换同义词。
5. 按当前消息中最新、最具体的格式要求确定最终容器和内容语法。
6. 检查平台格式、字数、占位符、标签、敏感承诺和隐私风险。

## 输出契约

默认输出“标题 + 正文”；用户要求时再增加话题标签、口播分镜或多个角度版本。成稿后只补充必要说明。

- 用户要求“不带 Markdown”时，成稿内部不使用 `#`、`-`、`**` 等 Markdown 排版符号。
- 用户随后明确要求“代码块方式输出”时，最新要求优先：用一个 fenced `text` 代码块包裹整份成稿，代码块内部保持纯文本。
- 不要在代码块外重复成稿；除非存在安全问题，代码块外也不追加格式解释、Skill 说明或新一轮字段清单。
- 必须出现但尚未提供的真实价格、品牌或产品属性使用明确占位符，不生成看似真实的数据。
- 用户要求输出整个文案时，完整成稿本身就是本轮唯一结果；不得以事实缺失为由退回信息收集模式。

## References 与 Templates

本 Skill 不依赖固定模板，以用户指定平台和素材为准。

## 边界

不保证流量或转化，不声称掌握平台最新算法。用户只要改写已有文字时使用 `rewrite-and-polish`；需要长篇论证时使用 `long-form-structure`。

## 示例

用户要求写儿童穿搭小红书时，应围绕真实穿搭场景、搭配思路和体感写作，不编造品牌合作、孩子评价或面料检测结论。

用户先说“价格要写，不要 Markdown”，但没有给真实价格，随后说“代码块方式输出”时，应直接给一个 `text` 代码块；代码块内部是纯文本成稿，并用 `[待填写：真实价格]` 占位。不要再次询问品牌、材质、尺码等全部字段。

## 常见错误

- 标题与正文重点不一致；
- 所有渠道都使用同一种网感语气；
- 为增强说服力补造体验和数字；
- 多个版本只是替换少量词语。
- 用户已要求代码块，却只展示代码块格式示例或继续追问；
- 同时把“不要 Markdown”和“代码块输出”理解为无法执行的矛盾要求。
