# 工作消息写作

## 目标

生成对象明确、结论靠前、行动项清楚且语气符合关系场景的工作邮件或即时消息。

## 必要输入

- 接收对象和双方关系；
- 沟通目的、必要背景和期望动作；
- 截止时间、渠道、语气及必须保留的信息。

## 硬门禁

- 不虚构审批、授权、截止日期、组织规定或对方承诺。
- 不把用户的猜测写成对他人动机或表现的事实判断。
- 不代用户作出未获授权的承诺、威胁或法律结论。

## 执行流程

1. 确定对方读完后应知道什么、做什么、何时完成。
2. 选择适合邮件或 IM 的长度和正式程度。
3. 先写结论或请求，再补最少必要背景、时间和材料。
4. 检查称谓、行动主体、截止时间、附件和回复方式。
5. 去掉空泛客套、被动攻击和可能引起歧义的表达。

## 输出契约

默认只输出可直接发送的正文；邮件场景按需包含主题。用户要求不同语气时提供有实质差异的版本。

## References 与 Templates

本 Skill 不依赖额外文件。完整项目汇报使用 `status-reporting`；敏感关系沟通使用 `difficult-workplace-conversation`。

## 边界

本 Skill 处理单次、边界清楚的工作消息，不替用户决定组织政治、劳动法律或重大谈判策略。

## 示例

确认交付时间的消息应包含当前依赖、需要对方确认的具体日期和回复动作，而不是只说“麻烦尽快看看”。

## 常见错误

- 背景过长，行动项藏在结尾；
- 没写清谁在何时做什么；
- 用模糊客气话代替明确请求；
- 擅自补充组织政策作为压力。
