# Web Chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** Add a local Gin Web chat service with anonymous browser users, MySQL-backed conversation management, detailed message history, live pi status events, and run cancellation.

**Architecture:** A new cmd/server Fx graph serves Go templates and Vanilla JavaScript through Gin. HTTP controllers call application/service/chat, which uses a new conversation-management repository alongside the existing conversation.Runner; pi remains unchanged and is observed through its existing Reporter contract.

**Tech Stack:** Go 1.26, Uber Fx, Gin 1.10, go-gin-sdk 0.0.6, go-context-sdk 1.0.2, GORM/MySQL, Go html/template, Vanilla JavaScript, CSS, SSE over streamed fetch.

**Spec:** docs/superpowers/specs/2026-08-14-web-chat-design.md

## Global Constraints

- Do not create, modify, rename, or delete any file under pi/.
- Preserve the one-shot behavior and tests of cmd/reagent and application.AgentRunner.
- Follow the sibling micro-framework directory layout, Fx registration style, Controller/Application/Domain/Infrastructure boundaries, Go-template organization, and Vanilla JavaScript conventions for all new Web code.
- Keep existing go-reagent packages in place; do not perform unrelated directory migration or refactoring.
- Use explicit SQL migrations; do not call GORM AutoMigrate.
- Bind the Web server to 127.0.0.1 by default and reject cross-origin state-changing requests.
- MySQL is mandatory for cmd/server; conversation.enabled must be true.
- The model response remains non-token-streaming; SSE exposes existing thinking, tool, final-message, and terminal events only.
- Keep the frontend build-free: no npm, React, Vue, bundler, or generated asset output.
- Apply TDD to every Go behavior: write and observe the focused failure before production implementation.
- Preserve unrelated worktree changes and stage only task-owned files in each commit.
